## データフロー

### 平常時(定時観察: 1 日 2〜4 回)

1. ESP32 が定期的に `picopico/basil/sensor/+` にセンサー値を publish(例: 30 秒ごと)
2. Pi は受信値を `sensors` テーブルに追記
3. 観察時刻になると、Pi が
   - USB Webカメラで鉢を撮影(`captures/` に保存)
   - 直近 24h のセンサー時系列を集計
   - 前回の `decisions` を読み出す
   - Claude API に画像 + 数値 + 前回判断を送って JSON 応答を得る
4. Pi の `safety` モジュールが応答をクリップ/拒否判定
5. OK なら `picopico/basil/command/pump` を ESP32 に送信し給水
6. 結果を `decisions`, `api_logs`, `watering_history` に保存
7. 重要イベントは LINE Messaging API で通知

### センサー異常時(臨時トリガー)

- 鉢重量が急激に変化、温湿度が極端、タンク空などを検知した場合に、
  定時を待たず Claude に臨時で判断を仰ぐ(あるいは即座にルールベースで停止する)

## 冗長性の設計意図

本プロジェクトでは「落ちてはいけない場所を小さく」する。

| 障害 | 期待する挙動 |
|------|-------------|
| Claude API ダウン/タイムアウト | Pi のルールベース判定にフォールバック。植物は死なない |
| インターネット断 | ローカル MQTT は生きるので観察ログは継続。判断はルールベース |
| Pi ダウン | ESP32 は最後のコマンドを保持 → 現状維持。追加給水しない |
| Wi-Fi 断(ESP32 側) | ESP32 はポンプを OFF に戻して待機(フェイルセーフ) |
| タンク空 | フロートスイッチで Pi が検知。すべての給水判断を拒否 |
| MQTT ブローカー再起動 | ESP32 は自動再接続、Pi は last will で状態復旧 |

「Claude API の提案を Pi のガードがクリップする」構造により、
Claude が 10 倍の給水量を返しても、無線が切れても、電源が落ちても、
植物は枯れない・水没しない設計になっている。
