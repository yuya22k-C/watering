# CLAUDE.md — プロジェクト憲法

このファイルは Claude Code と開発者が共有する、本プロジェクトの不変ルールを定めるものです。
実装判断に迷ったときは、まずこのファイルを参照してください。

---

## 1. プロジェクト概要

- **プロジェクト名**: basil-ai（「AIにバジル栽培させてみた」）
- **形式**: YouTube 動画企画用 IoT システム
- **チャンネル**: ワンルーム農園（登録者目標 2 万人）
- **栽培対象**: スイートバジル（Ocimum basilicum、室内栽培）
- **中心となる検証**: Claude API に水やりの可否と量を判断させ、その過程を映像化する
- **対照実験**: 同じハードウェア・環境条件で人間が手動管理する対照群を並行運用し、AI 個体と比較する

「動画として面白い失敗」と「植物を枯らさない安全性」を両立させることが設計の芯です。
Claude の判断を尊重しつつ、決定的な破壊（枯死・水没・過給水）は Pi 側のセーフティガードが必ず防ぎます。

---

## 2. アーキテクチャ（3 層）

```
[ESP32 Freenove] ──MQTT──> [Raspberry Pi 4B] ──HTTPS──> [Claude API]
     │                           │
 センサー読み取り              画像撮影
 ポンプ制御                   ルールベース判定
 判断はしない                 セーフティガード
                              LINE Messaging API 通知
```

### 第 1 層: ESP32 (Freenove ESP32-WROVER)
- 役割: センサー値収集、ポンプ駆動、LED 制御、MQTT 送受信
- 非役割: 判断ロジックを持たない。常に Pi からの指示で動く
- ネットワーク断時の挙動: 現状維持（ポンプ停止・最後の指示を保持）

### 第 2 層: Raspberry Pi 4B
- 役割: ゲートウェイ、USB Webカメラによる画像取得、Claude API 呼び出し、
  セーフティガード、SQLite ログ、LINE Messaging API 通知
- Mosquitto（ローカル MQTT ブローカー）をホスト
- Claude API が落ちていてもローカルのルールベース判定で給水可否を決められること

### 第 3 層: Claude API
- 役割: 画像と数値時系列を受け取り、給水可否と推奨 ml を JSON で返す
- 最終決定権は Pi のセーフティガードが持つ。Claude の応答は「提案」であって「命令」ではない

## 3. 確定している設計判断

以下は本プロジェクトで確定済みの決定事項です。変更する場合は明示的な合意が必要です。

| 項目 | 決定 |
|------|------|
| MQTT ブローカー | Pi 上の Mosquitto（ローカル完結） |
| クラウド MQTT | 使わない（HiveMQ Cloud などは対象外） |
| 通知チャンネル | LINE Messaging API |
| Claude API 呼び出し頻度 | 1 日 2〜4 回の定時観察 + センサー異常時トリガー |
| 土壌水分計測 | 静電容量式センサーのみ |
| 重量計測 | ロードセル 5kg + HX711（土壌水分センサーより信頼性高） |
| カメラ | USB Webカメラ（Logicool C270 または C920） |
| ポンプ | ペリスタルティックポンプ 12V + DRV8833 |
| タンク空検知 | フロートスイッチ |
| Pi 側言語 | Python（venv） |
| 主要 Python パッケージ | anthropic, python-dotenv, opencv-python, paho-mqtt |
| DB | SQLite、4 テーブル（sensors / decisions / api_logs / watering_history） |
| 鉢 | 6 号鉢 |
| LED | 植物育成 LED（USB 給電、全波長） |
| 3D プリント素材 | PETG（ロードセル台座・カメラマウント） |

## 4. 禁止事項（絶対に守る）

以下は技術的・運用的な理由で本プロジェクトでは使用しません。
Claude Code がコード生成・提案を行うとき、これらを含む案は即座に却下してください。

### 4.1 LINE Notify を使わない
- **理由**: LINE Notify は 2025 年 3 月末でサービス終了済み
- **代替**: LINE Messaging API（チャンネルアクセストークン + ユーザー ID）

### 4.2 抵抗式土壌水分センサーを使わない
- **理由**: 電極が腐食し、数週間で値がドリフトする。長期栽培に使えない
- **代替**: 静電容量式センサー v2.0

### 4.3 ESP32-CAM を使わない
- **理由**: 画質・露出制御・長期安定性が室内植物撮影に不十分。電源・熱問題もある
- **代替**: Raspberry Pi に接続した USB Webカメラ（C270 / C920）

### 4.4 判断ロジックを ESP32 に持たせない
- **理由**: 3 層構成の責務分離を崩すと、障害時の挙動が予測不能になる
- **ESP32 は「センサー読み取り」と「Pi から来た指示の実行」のみ**。
  どの条件で給水するかの判断は Pi とその先の Claude API に集約する

### 4.5 クラウド MQTT を使わない
- **理由**: 本プロジェクトはローカル完結で動くことを要件とする。
  外部サービス依存を最小化し、ネットワーク断でも ESP32↔Pi 間は生かす
- **代替**: Pi 上の Mosquitto

## 5. 責務分離の原則

| 層 | やること | やらないこと |
|---|---|---|
| ESP32 | センサー読み取り、ポンプ駆動、MQTT 送受信 | 判断、しきい値判定、Claude 呼び出し |
| Pi | ゲートウェイ、画像、ルールベース判定、ガード、ログ、通知 | ハードウェア直接制御（ESP32 経由） |
| Claude API | 画像 + 数値から給水提案を JSON で返す | 最終決定、ハードウェア制御 |

**この境界を越える実装は原則として却下する。**

## 6. セーフティガードの原則

詳細は `docs/safety-guards.md` に記すが、CLAUDE.md レベルで不変の原則を置く。

- Claude API の応答は「提案」として扱う。Pi のガードが最終決定する
- 1 回の給水量には上限がある。Claude が上限を超える ml を返してきても Pi がクリップする
- 直前の給水からクールダウン時間が経過していない場合、Claude が「給水」と判断しても Pi が拒否する
- Claude API タイムアウト・エラー時は、Pi のローカルルールにフォールバックする（絶対に例外で落ちない）
- タンク空（フロートスイッチ反応）時は、いかなる判断でも給水しない

## 7. 開発スタイル

- コミットメッセージは変更の「なぜ」を短く書く
- 日本語コメント OK。ただしコード中のコメントは「なぜそうしたか」が非自明なときだけ
- Python は Pi 側、C++/Arduino(PlatformIO) は ESP32 側
- 機能追加前にまずドキュメントを更新する（このプロジェクトは動画化が目的なので、
  後から「なぜそうしたか」を説明できる状態を保つ）

---

## 8. 対照実験の記録方針

- AI 個体・人間管理個体の両方に同じセンサー一式を付ける（ただしポンプは AI 個体のみ自動）
- 人間管理個体の給水も `watering_history` に手動で記録する（動画編集で比較映像を作るため）
- 両個体の写真を同じ時刻・同じアングルで毎日撮る
